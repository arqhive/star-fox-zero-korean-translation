# 파일 포맷과 패치 방식

## 전체 흐름

```
data003.cpk (CRI CPK)
  └ ui/*.dat (PlatinumGames DAT, 빅엔디언)
      ├ mess*.mcd  — 메시지 + 심볼표 + 글리프표 + 폰트표 + 이벤트표
      ├ mess*.wta  — GX2 텍스처 헤더
      └ mess*.wtp  — 글리프 아틀라스 픽셀 (RG8, swizzle 적용)
```

번역은 MCD 의 텍스트와 심볼표를 새로 쓰고, 그 파일이 쓰는 글자만 모아 아틀라스를 다시 그리는 방식이다.

## CPK

- 비암호화 CRI CPK. 헤더·TOC·ETOC 가 `@UTF` 테이블.
- 파일은 대부분 CRILAYLA 압축. 패치는 교체 파일을 **비압축**으로 넣는다(`FileSize == ExtractSize`).
- 재작성 시 TOC 의 `FileOffset/FileSize/ExtractSize`, 헤더의 `ContentSize/EtocOffset` 을 갱신한다.
- TOC 의 파일별 `CRC` 와 헤더 `TocCrc` 는 알고리즘을 알아내지 못해 원본 값을 유지한다.
  실기·Cemu 모두 문제없이 동작한다(CRI 런타임이 검사하지 않음).

## DAT

헤더 8×u32: 매직 `DAT\0`, 파일 수, 오프셋표, 확장자표, 이름표, 크기표, 해시맵, 예약.
재패킹 규칙: 파일은 인덱스 순서, `.wtp` 는 0x2000 정렬, 나머지는 0x40 정렬, 파일 끝은 0x2000 정렬.

## MCD (메시지)

헤더 10×u32 = (메시지, 심볼, 글리프, 폰트, 이벤트) 각각의 오프셋·개수.

| 표 | 크기 | 내용 |
|---|---|---|
| 메시지 | 16 | 섹션 오프셋, 섹션 수, 시퀀스 번호, 해시 |
| 섹션 | 20 | 줄 오프셋, 줄 수, 섹션 인덱스, 예약, `폰트ID<<16` |
| 줄 | 24 | 텍스트 오프셋, 0, 길이, 길이, below/horiz(float) |
| 심볼 | 8 | 폰트ID(u16), UTF-16 문자(u16), 글리프 인덱스(u32) |
| 글리프 | 40 | 텍스처 해시, u1,v1,u2,v2, 폭, 높이, 0, below, horiz |
| 폰트 | 20 | 폰트ID, 공백 폭, 높이, below, horiz |
| 이벤트 | 40 | 해시, 메시지 인덱스, 이름[32] |

텍스트는 u16 쌍의 나열이다: `(심볼 인덱스, 커닝)`. 제어 코드는 `0x8001 폰트ID`(공백),
`0x8003 n`(버튼 아이콘), `0x800C/0x800D q`(아이콘 묶음), `0x8000`(줄 끝).
각 표는 바로 앞 표가 끝난 위치에서 **다음 4의 배수**부터 시작한다(패딩 1~4바이트).

## 글리프 아틀라스

- `.wtp` 는 GX2 텍스처. 메시지용은 `UNORM_R8_G8`(fmt 0x7), R = 글자 + 1px 외곽선, G = 글자 본체.
- `tileMode 4`, `swizzle 0x000d0000` 이라 AddrLib 의 주소 변환(deswizzle/swizzle)이 필요하다.
- 파일마다 쓰는 글자만 들어 있다. 번역 후에는 실제로 쓰인 `(폰트, 글자)` 조합만 모아
  스카이라인 패킹으로 다시 배치하고, 원본에 있던 글자는 원본 픽셀을 그대로 재사용한다.
- 다중 텍스처 `.wta` 의 GX2 레코드 간격은 0xC0.
- 크기를 바꿀 때 갱신할 필드: 정보 오프셋 +4(w,h), +0x20(imageSize), +0x3C(pitch),
  +0x88 = `(w-1)<<19 | (w/8-1)<<8 | 하위바이트`, +0x8C 의 하위 13비트 = `h-1`, 크기표 = imageSize + 0x11C.

## 한글 글리프 렌더링

`tools/font_render.py` 의 `STYLES` 에 폰트ID별로 원본에서 측정한 값을 넣어 둔다
(글자 높이, 굵기, 인위적 굵기, 외곽선 두께, 좌우 여백). 4배 슈퍼샘플링으로 그린다.
원문은 음수 커닝으로 자간을 좁히지만 번역문은 커닝 0을 쓰므로, 대신 한글 좌우 여백을 절반으로 줄인다.

굵기는 `tools/stroke_check.py` 로 맞춘다. 폰트ID별로 원본 일본어 글리프와 한글 글리프의
평균 획 두께(거리변환 능선값 ×2, 문턱값 5개 평균)를 비교해 비율을 내고, 1.00에서 크게 벗어나면
`STYLES` 의 `wght`(Noto 가변 굵기)·`emb`(덧칠 두께)를 조정한다. 아틀라스는 메모리에서만 만들므로
빌드 없이 돌릴 수 있다. 2026-10-03 기준 폰트 5는 덧칠을 빼서 1.38배 → 1.03배로 맞췄고,
폰트 1(1.12배)은 차이가 작아 그대로 두었다. 나머지는 0.92~1.06배.

덧칠은 **가로 방향으로만** 준다(`_hdilate`). 사방으로 굵게 하면 ㅌ·ㅂ·ㅊ처럼 가로획이 촘촘한
자모의 틈이 막혀 「통」이 뭉개진다. 외곽선만 사방으로 둔다. 그래서 덧칠을 쓰는 폰트(3·4·8·10)는
가로획이 원본보다 얇아 stroke_check 비율이 0.85 안팎으로 나오지만, 세로획 굵기와 글자 폭은 같다.

한글이 쓰이는 폰트(`STYLES` 에 있는 폰트)에서는 가나·한자를 뺀 모든 글자(영문·숫자·기호·그리스 문자·
「」)를 원본 글리프 대신 Noto 로 다시 그린다(`font_render.redraw`). 한글이 없는 폰트(스태프 롤·
저작권 표기·숫자 전용)는 원본 그대로다. 폭은 Noto 에 설계된 진행 폭 + 외곽선이고, 원본 글리프 폭을
넘지 않게 잘라 줄 길이가 원본보다 늘지 않는다. 숫자만은 상한을 두지 않는다 — Noto 숫자는 0~9 폭이
같아서(고정폭) 그대로 써야 점수·시간 표시의 자리가 흔들리지 않고, 모든 폰트에서 원본 숫자보다 좁다.
「」 같은 CJK 구두점은 전각 칸 대신 잉크 기준 폭으로 둔다. `lint.py` 의 `char_adv` 가 같은 규칙으로
줄 폭을 계산한다.

## 이미지 텍스트

- 타이틀 로고: `ui_title.dat` 의 0번 텍스처(RGBA8 2048×1024) 두 곳.
- 엔딩 청구서: `ui_ending.dat` 의 1번 텍스처(BC1 1024×1024). 일본어를 지우고 주변 종이색으로 메운 뒤
  한글을 그리고, **바뀐 4×4 블록만** 자체 BC1 인코더로 다시 압축한다.
- 그 밖의 텍스처 약 3,800장은 전수 확인했고 번역이 필요한 일본어는 없다.

## 검사 도구

`tools/lint.py` — 태그 개수 불일치, 일본어 잔존, 줄 폭 초과(같은 파일·폰트의 원문 최대 폭 기준),
줄 수 초과를 검사한다. 글자 폭은 원본 글리프 폭과 새로 렌더링한 글리프 폭으로 계산한다.
